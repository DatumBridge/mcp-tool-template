# ADR-0001 — Tool-server, not a relay

## Context

Weaver installs MCP servers by building a container and calling Streamable HTTP. A second shape in this platform relays MCP to a device over a socket. Mixing them copies pairing and device state into API tools.

## Decision

This repository is a tool-server. Tools run here and call one upstream. Device relay stays out.

## Alternatives Considered

- Copy the WebSocket hub. Rejected. That hub is the relay class.
- One process for several unrelated providers. Rejected until a product case names them.

## Consequences

- `GET /health` and `POST /mcp` are the platform surface.
- Guides in `registry_docs/` are required for every tool.
- Port 8000 and protocol `2024-11-05` match the registry client.

## Trade-offs

A new provider needs a new repository. That keeps credentials and guides scoped.

## Risks

A later change could add a socket "just in case." `design.md` non-goals forbid that without a new ADR.
